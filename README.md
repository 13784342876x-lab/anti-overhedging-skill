# Anti-Overhedging Skill · 反过度防御写作

减少预先澄清、姿态性让步和重复限定，让核心判断、依据和适用范围更清楚。

## 文件

- [SKILL.md](SKILL.md)：完整技能指令，包含写作规则、改稿流程、语义检查和示例。

## 适用任务

- 新写文章、报告、项目申报、邮件和解释性文字。
- 保留原意，删除改稿中的过度防御。
- 诊断哪些让步和限定有必要，哪些只是表达姿态。

## 使用

将本仓库的 SKILL.md 放入所用工具的技能目录下，目录名使用 anti-overhedging-skill，并按该工具的技能加载方式启用。

支持技能调用的环境中，可使用：

> 请用 $anti-overhedging-skill 修改下面这段文字，保留原意，直接给出改稿。

新写：

> 请用 $anti-overhedging-skill，根据以下材料写一篇面向产品经理的文章。先陈述核心判断，再展开原因和证据。材料如下：……

诊断：

> 请用 $anti-overhedging-skill 检查下面的文字，列出过度防御的表达，说明保留或删除的理由，并给出改稿。

尚未安装技能时，也可以将 SKILL.md 正文作为写作要求提供给模型。

## 核心原则

1. 先说判断，再给原因、证据和必要边界。
2. 只回应与目标读者和论证有关的反对意见。
3. 用具体信息替代泛泛的态度表述。
4. 每段完成一个主要任务。
5. 让转折词表达真实的逻辑关系。
6. 精简不能改变原意、事实范围或结论强度。

“可能”“这并不意味着”“并非……而是……”等是检查信号，并非禁用词。决定结论是否成立的条件应当保留。

## 示例

原文：

> 这并不意味着数据越多，模型效果就一定越好。

改写：

> 增加数据量不一定能改善模型效果。

不将它改为“数据质量比数据数量更重要”：该说法增加了原文没有提供的优先级判断。

## 思路来源

本技能根据用户提供的文章[《ChatGPT的写作姿态：过度防御》](https://mp.weixin.qq.com/s/JutiBl6wh02-GPPMDova6g)整理，并加入了命题强度、语义等价和不编造细节的检查规则。

本仓库提供可执行的写作指令，不收录原文全文。
